## 2026-03-31 - [KaTeX XSS Prevention & Dependency Sync]
**Vulnerability:** KaTeX versions prior to 0.16.21 contained multiple moderate vulnerabilities related to URL normalization, `\includegraphics` escaping, and `maxExpand` bypasses. Additionally, rendering math using `dangerouslySetInnerHTML` without post-parsing sanitization posed a persistent XSS risk if the math engine or AI provider were compromised.
**Learning:** In a project using both a local `package.json` and a browser-side `<importmap>`, security updates must be synchronized across both to ensure consistent protection between dev and production builds. Simple KaTeX rendering is not inherently safe; it produces raw HTML that should be treated as untrusted input.
**Prevention:** Always sanitize KaTeX output with a library like DOMPurify, specifically enabling the `mathMl` profile. Maintain strict version parity between `package.json` and `index.html` CDN links to prevent "version drift" where the local environment seems secure but the production environment remains vulnerable.
