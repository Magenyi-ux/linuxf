## 2025-05-15 - XSS via Unsanitized KaTeX Output
**Vulnerability:** KaTeX `renderToString` produces HTML that was directly passed to `dangerouslySetInnerHTML` in `MathText.tsx`. This could allow Cross-Site Scripting (XSS) if the input math string (which can come from AI or external sources) contains malicious payloads that KaTeX doesn't fully neutralize, or if an older version of KaTeX is used.
**Learning:** In a React application using KaTeX, `dangerouslySetInnerHTML` is often necessary for rendering math, but it must be paired with a sanitizer like DOMPurify. To preserve KaTeX's specific output (including SVGs and MathML), DOMPurify needs a specific profile configuration: `{ USE_PROFILES: { html: true, svg: true, svgFilters: true, mathMl: true } }`. Additionally, browser-side dependencies managed via an `importmap` in `index.html` must be kept in sync with `package.json`.
**Prevention:** Always sanitize any HTML string before passing it to `dangerouslySetInnerHTML`. Maintain a strict synchronization process between `package.json` and the `index.html` `importmap` to ensure consistent security patches across all environments.
